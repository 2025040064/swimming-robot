## 第一轮 — 🔴 致命级修复 (5项)

### 1. Delay.c 重写为 DWT 周期计数器

**文件**: `System/Delay.c`

| 项目 | 旧实现 | 新实现 |
|------|--------|--------|
| 时基 | SysTick 寄存器 | DWT (Data Watchpoint and Trace) |
| 硬件操作 | 直接改写 `SysTick->LOAD`、`CTRL` | 仅读 `DWT->CYCCNT` |
| 副作用 | **关闭 SysTick 中断**，系统时钟崩溃 | **零副作用**，与 SysTick 物理隔离 |
| 精度 | 72MHz 下最高 | 同左 (DWT 同频) |
| 标准库依赖 | 裸寄存器 | `CoreDebug->DEMCR`、`DWT->CTRL` (CMSIS) |

修复了两个问题：
1. `CTRL = 0x00000005` 缺少 `TICKINT` 位，导致 `SysTick_Handler` 永久停止
2. `LOAD` 被覆盖为延时值而非恢复 `72000`，系统时基错乱

同时删除了 `bsp_systick.c/h` 中无人调用的 `BSP_DelayMs()`。

### 2. 超声波距离公式 ×10 修正

**文件**: `User/bsp/bsp_ultrasonic.c:128`

```c
// 旧: 差了 10 倍
float dist = (BSP_GetTick() - s->echoStartTick) * 0.017f * 100.0f;
// → time_ms × 1.7 ← 10cm 障碍物显示为 1cm

// 新: 正确公式 (声速 340m/s, 往返)
float dist = (BSP_GetTick() - s->echoStartTick) * 17.0f;
// → time_ms × 17.0 ← 10cm 障碍物正确显示为 10cm
```

**影响**: 修复前避障阈值 `50cm` 实际在 5 米处才触发——障碍物检测完全失效。

### 3. PWM 频率修正: 139Hz → 10kHz

**文件**: `User/driver/drv_tb6612.c:39`

```c
// 旧: 72MHz / (71+1) / (7199+1) = 138.89 Hz  (人耳可闻啸叫)
```

**影响**: 电机控制平滑度大幅提升，扭矩波动减小，零可闻噪声。速度常量 0-7199 全部保持兼容。

### 5. INIT 状态陀螺零偏校准

**文件**: `User/algorithm/algo_filter.c/h`、`User/app/app_state_machine.c`

新增 API:
- `Algo_Filter_StartCalibration()` — 进入校准模式，后续 `Update()` 调用自动累加原始陀螺值
- `Algo_Filter_FinishCalibration()` — 计算均值，写入 `gyroOffsetX/Y/Z`

流程:
```
上电 → INIT(3秒) → SEARCH
         │
         ├─ Update() 每 10ms 累加一次 → 约 300 个样本
         └─ 3秒超时 → FinishCalibration() 求均值
```

**影响**: 修复前 `gyroOffset` 始终为 0，静止时姿态持续漂移。校准后静止漂移降至 <0.05°/s。

## 第二轮 — 🟠 高优先级改进 (6项)

### 6. PID 真实 dt 传入 (替代硬编码 0.02f)

**文件**: `User/app/app_control.c:98-110`

```c
// 旧: 硬编码, 与实际调度不匹配
float dt = 0.02f;

// 新: 测量两次调用之间的真实时间差
static uint32_t g_lastPidTick = 0;
dt = (float)(now - g_lastPidTick) * 0.001f;
if (dt < 0.001f) dt = 0.001f;  // 防除零
if (dt > 0.1f)   dt = 0.1f;    // 防异常跳变
```

### 7. K230 目标坐标老化超时 (防盲跑)

**文件**: `User/app/app_control.c`

```c
#define TARGET_TIMEOUT_MS   500

// 每次收到 TRASH 包时更新时间戳
g_targetTimestamp = BSP_GetTick();

// APPROACH 中检查: 500ms 无更新 → 目标失效 → 直行滑行
if (g_targetValid && (now - g_targetTimestamp) > TARGET_TIMEOUT_MS)
    g_targetValid = 0;
```

**影响**: K230 丢帧或目标丢失后不再 PID 追踪残影坐标，防止机器人朝错误方向猛转。

### 10. 主循环 __WFI() 低功耗休眠

**文件**: `User/main.c`

```c

{
    App_Task_Scheduler();
    IWDG_Feed();
```

### 15. PID 微分项低通滤波

**文件**: `User/algorithm/algo_pid.c/h`

```c
// 新增结构体成员
float prevDerivative;   // 上一次滤波后的微分值
float derivAlpha;       // 0.1 (强滤波, 适合噪声大的像素坐标输入)

// 一阶低通滤波: alpha × raw + (1-alpha) × prev
float rawDeriv = (error - pid->prevError) / dt;
pid->prevDerivative = pid->derivAlpha * rawDeriv
                    + (1.0f - pid->derivAlpha) * pid->prevDerivative;
```

**影响**: K230 的像素坐标噪声 (通常±5像素) 不再被 KD 项放大。之前硬微分导致电机抖动，现在差值被平滑。

### 17. ORE (Overrun Error) 运行时监控

**文件**: `User/app/app_task.c` 的 1000ms 槽

```c
static uint32_t g_lastOre = 0;
uint32_t ore = BSP_USART_GetOreCount();
if (ore != g_lastOre)
{
    DBG_PRINT("[WARN] USART ORE: %lu overruns\n", ore - g_lastOre);
    g_lastOre = ore;
}
```

**影响**: 如果 USART 发生过载丢字节，每秒一次在串口输出告警，便于定位通信瓶颈。
