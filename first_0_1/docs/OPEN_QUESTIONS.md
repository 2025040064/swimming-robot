Actual OLED VDD voltage, controller model, onboard pull-ups and the result after flashing this fix remain unverified.
- 2026-09-11: With PB12/PB13 and PB14/PB15 both connected, propulsion remained stopped; disconnecting either wire in either pair allowed the corresponding motor to run and MPU-based stopping had some effect. Exact STM32-to-D153C terminal mapping and measured AIN/BIN voltages remain unverified. Firmware now displays the PB12-PB15 output/readback nibbles for diagnosis.
- 2026-09-11: A temporary positive-only bench workaround was tested: PB12/PB14 were push-pull drive outputs and PB13/PB15 were pull-down inputs. It did not change the reported behavior and is now disabled; PB12-PB15 are all push-pull outputs again.
- 2026-09-11: Because the one-wire workaround produced the same reported behavior, a reset-time direction diagnostic now commands both channels as 10 for 1.5 s, stops for 0.75 s, commands 01 for 1.5 s, then stops before normal MPU initialization. The observed result with all four direction wires connected is still required to distinguish firmware download from D153C terminal/wiring faults.
- 2026-09-11: The direction diagnostic did not rotate either motor with all four wires connected. The user later corrected the key observation: after disconnecting the wire called PB15, connecting it to any STM32 pin makes the motor rotate. This pin-independent behavior makes a missing or unreliable common ground between the Blue Pill, D153C and motor battery the first hardware condition to verify. Wiring labels were subsequently confirmed by the user.
- 2026-09-11: A full wiring photo was supplied. It confirms the propulsion board uses a right-edge signal header, but crossing wires obscure the header labels and the endpoints of the PB14/PB15 wires. The photo is insufficient to prove pin-to-terminal mapping; a close view of only the driver header, with the wire colors and silkscreen visible, or a written color-to-label list is still required.
- 2026-09-11: The user confirmed the D153C signal wiring is correct. The temporary one-wire workaround is therefore disabled: PB12-PB15 return to push-pull direction outputs. The reset-time direction diagnostic is raised from PWM 2000 to 7199 because the previously successful fixed-speed test used full duty and 2000 may be below the loaded motor's start threshold. Hardware behavior after flashing this build remains unverified.
- 2026-09-11: Power-off continuity tests now confirm Blue Pill GND, D153C GND and motor-battery negative are connected, so missing common ground is excluded. The user reports that moving any one direction wire to any MCU pin still makes the motor rotate; this test leaves TB6612 inputs at uncontrolled/default levels and does not establish the commanded logic state. Simultaneous powered measurements at the D153C AIN1/AIN2/BIN1/BIN2/PWM/STBY terminals are still required.
- 2026-09-11: The OLED remains black after previously showing a startup page. The firmware never deliberately sends display-off during runtime. Remaining leading causes are OLED power/reset disturbance during motor current changes, loss of I2C ACK or a held-low PB10/PB11 line, and unconfirmed controller/pull-ups. Read g_debugOledStatus/address/noAckCount before further display changes.
- 2026-09-11: The user reports the PC13 board LED changes from fast to slow. Current firmware has competing LED writers during the approximately three-second INIT calibration and a separate 200 ms MPU-startup fault loop, so the visual pattern alone is ambiguous. g_debugBootStage, g_debugRunTick, g_debugState and g_debugImuStopReason are required to distinguish normal calibration from reset/startup failure.
